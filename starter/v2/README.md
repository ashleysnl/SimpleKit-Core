# V2 authored calculator starter

This template is a maintained shell skeleton, not a working calculator or an additional build framework. Existing tools retain their authored HTML, IDs and algorithms; use this only for a new page or an explicitly reviewed template change. [Style guide](../../docs/v2-authoring/calculator-style-guide.md), [spec](../../docs/v2-authoring/calculator-spec.template.yaml), [master prompt](../../docs/v2-authoring/master-codex-build-prompt.md).

Adopt a full immutable Core revision through the existing site/source build contract. Import `shellHeader`, `shellFooter`, `breadcrumbs` and `escapeHtml` from that revision's `v2/components.mjs`; do not write duplicate brand/navigation markup. Replace the named `{{...}}` slots through the existing owning build/template mechanism, as the site already does. Do not publish an unresolved template or treat a starter/example output as a calculated result.

Render `sharedHeader` with `shellHeader('Tools', 'your-tool', {mainId:'main'})`; render `sharedFooter` with `shellFooter()`. Generate breadcrumbs for the real hierarchy using canonical root-relative routes. Escape pageTitle, description, h1, introduction, toolId and family values. Validate canonicalUrl against the tool's existing manifest route before inserting its escaped value. `workingContent` is trusted authored HTML, not user input; it contains the real task-specific form and primary results with preserved labels, units, IDs, parsing and state. Choose the task layout deliberately; the starter supplies no fake formula or universal grid.

Keep meaningful assumptions, financial context and related routes in `assumptionsAndRelatedContent`. `preservedHead` holds existing analytics/schema/metadata not already represented by the template; avoid duplicate tags. `preservedScripts` holds unchanged task/financial/state logic and loading order. `toolStyles` adds only the source-owned adapter after shared CSS. Empty intentional slots still require explicit replacement. Fail the owning build if any `{{...}}` placeholder remains.

The portable site assembles `/assets/core/v2/` from its immutable source manifest. Standalone source previews must vendor/localize that same revision, including relative font/sprite resources and the shared renderer's asset alias. The example root URLs are not a promise that a separate GitHub Pages host has those files. Do not replace them with a mutable live CDN or mount legacy core.js beside the V2 shell.

The opt-in marker preserves legacy consumers. The header/footer carry theme 1.1; calculator primitives retain compact introductions. Footer support remains in flow. Keep keyboard/no-JS links available and defer whole-site acceptance to the consolidated final QA checkpoint. This starter is outside `v2/`, so the portable build does not copy it into a published calculator route automatically.
