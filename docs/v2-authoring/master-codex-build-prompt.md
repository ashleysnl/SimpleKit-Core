# SimpleKit V2 master Codex build prompt

Use this maintained prompt with the calculator's existing `calculator-spec.yaml`, local AGENTS.md and the current site roadmap. Legacy Factory paths are historical provenance if unavailable; do not block routine V2 work on those paths.

1. Inspect the working tree and preserve unrelated/uncommitted work. Synchronize the owning repository's `develop-v2`, confirm previous completed changes are integrated, and use that branch throughout. Do not create persistent task branches, reset divergent work, force-push, modify main/production/DNS or deploy without authorization.
2. Determine ownership before editing: common tokens/fonts/icons/shell/components belong in SimpleKit-Core; formulas/state/exports/task adapters belong in the calculator; routes/registry/assembly/homepage composition belong in simplekit-site. Read the Core authoring guide and adopted immutable runtime SHA. Reuse completed migrations and the CPP/Budget reference patterns.
3. Treat the local financial spec and existing behavior as authoritative. Preserve formulas, parsing/ranges/defaults/rounding, local state compatibility, IDs, imports/exports, URLs/metadata/content/schema and analytics. If a behavior change is requested, isolate it and run focused regression checks. Do not replace real outputs with starter/demo values.
4. Use the shared System v1/theme 1.1 opt-in contract and pinned local assets. Render one shared header/footer and actual breadcrumbs. Give the calculator a compact title/description, clear fields and prominent results. Keep appropriate guided/tabbed/dynamic-row/report workflows. Keep homepage imagery/search/discovery specific to the homepage and support in normal flow/footer.
5. Implement one coherent batch. Inspect the source diff; run the portable build once for that batch and a brief mobile/desktop look at touched pages. Check touched behavior or known defects. Defer exhaustive fixtures, broad audits, browser matrices and screenshot galleries to Phase 16; preserve mandatory CI. Record precise results and deferred checks without claiming acceptance from a passing build.
6. Commit/push completed source-owned work to its `develop-v2`; update the site's immutable source pins deliberately after source review/publication. Never author generated `dist/` or source caches. Documentation-only source updates need not repin unchanged runtime assets. Keep exact old/new revisions and rollback notes. If a temporary PR is required, target develop-v2 and integrate completed work promptly after validation.
7. Update the roadmap/handoff using `[ ]` incomplete, `[~]` in progress/unverified and `[x]` successfully verified. Report changed files/repositories/commits, checks, exceptions, remaining work and production status. Before final QA, review preserved divergent work and freeze the exact candidate. Release only through final QA → approved PR into main → explicitly authorized deployment.

Deliver a useful static tool, not a new framework or design system. A copied factory prompt must link to this maintained contract; changes to the external factory generator require its actual owning repository, not a chat attachment.
